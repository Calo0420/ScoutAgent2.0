## DELIVERABLE 1 — Executive Summary

### Purpose
Two-page maximum. Written for a CIO who has 5 minutes. No technical jargon. Leads with money and risk.

### Structure

**Page 1 — Situation and Findings**

- **Context:** Why was this assessment done, what environment was scanned
- **What We Found — Estate:** Number of servers, OS breakdown, end-of-support exposure
- **What We Found — Risk:** Top security findings, risk rating (CRITICAL/HIGH/MEDIUM/LOW)
- **What We Found — Opportunity:** Estimated savings, quick wins identified

**Page 2 — Priority Recommendations**

Up to 3 priorities, each containing:
- Action (what to do)
- Why it matters (business impact, not technical detail)
- Effort and cost estimate
- Expected outcome
- Which Apex accelerator delivers it

### Language Rules
**DO:** Use dollar figures. Use percentages. Name specific servers only when critical.
**DO NOT:** Use acronyms without definition. Lead with technology. Say "we recommend" without a reason.

- Failed logins >50 → **BRUTE FORCE INDICATOR**
- Disk >80% → **CAPACITY RISK**

## DELIVERABLE 3 — Risk Map

### Purpose
Visual and tabular representation of every security finding. Primary input for CISO conversation.

### Risk Heat Map

Each finding is rated on two axes:

- **Likelihood:** How likely is this to be exploited (1=Rare, 5=Almost Certain)
- **Impact:** What is the business impact if exploited (1=Negligible, 5=Critical)
- **Score:** Likelihood × Impact (1-25)

| Score | Rating | Color |
|---|---|---|
| 20-25 | CRITICAL | Red |
| 12-19 | HIGH | Orange |
| 6-11 | MEDIUM | Yellow |
| 1-5 | LOW | Green |

## DELIVERABLE 4 — Savings Estimate

### Purpose
The financial case. Written for CFO and procurement. Every number needs a confidence level.

### Structure

**Section 1 — The Investment**
What Apex is proposing and what it costs (delivery hours, licensing if any).

**Section 2 — The Return**

| Scenario | Annual Savings | Break-Even | Requirements |
|---|---|---|---|
| Conservative | $X | Y months | Powered-off VMs reclaimed only |
| Moderate | $X | Y months | + VM rightsizing applied |
| Aggressive | $X | Y months | + Full Linux migration eligible servers |

**Section 3 — 3-Year Perspective**

| | Year 1 | Year 2 | Year 3 | Total |
|---|---|---|---|---|
| Current cost | | | | |
| Projected cost | | | | |
| Cumulative savings | | | | |

**Confidence Level Statement**
Always include: HIGH / MEDIUM / LOW confidence declaration based on data quality.
- HIGH: full vCenter access, accurate license data provided
- MEDIUM: partial data, estimates used for missing servers
- LOW: sample only, full environment not scanned

## DELIVERABLE 6 — Migration Roadmap

### Purpose
The "what happens next" document. Gives the client a concrete path forward tied to real effort estimates.

### Phase Structure

| Phase | Timeline | Scope | Key Activity | Value Delivered |
|---|---|---|---|---|
| Phase 1 — Quick Wins | Days 1-30 | Security fixes, powered-off VM cleanup | CIS hardening, reclaim licenses | Risk reduction, immediate savings |
| Phase 2 — Stabilize | Days 31-60 | Patch gaps, monitoring, auditd | Patch all flagged servers, enable logging | Compliance readiness |
| Phase 3 — Modernize | Days 61-90 | Linux migration eligible servers | Pilot migration, validate workloads | TCO reduction begins |

### Per-Phase Detail
Each phase must include:
- Server list in scope
- Step-by-step activities
- Resource estimate (hours)
- Prerequisites
- Success criteria (measurable)

### Out-of-Scope Servers Table

| Hostname | Role | Blocker | Review Trigger |
|---|---|---|---|
| server05 | Legacy ERP | Vendor dependency | Contract renewal Q3 |
| server08 | Domain Controller | AD migration required first | Phase 2 complete |
